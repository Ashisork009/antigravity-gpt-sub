# 弹性蜂群与五大专项蓝图

只读与当前任务相关的章节。角色数量随独立写集、依赖关系和风险动态伸缩，不套用固定编制。

## 一、通用弹性蜂群框架

### 1. 按规模动态裁剪

| 规模 | 执行层 | 运维 / 审查 | 统筹 / 规划 / 文档 |
| :--- | :--- | :--- | :--- |
| **小型**（单写集、低风险） | 1 名 `sol-high` | 省略；有非显而易见风险时加 1 次 `astra-high` 只读审查 | 主控（Neon）直接定契约、收口并更新重要文档 |
| **中型**（2–4 个独立写集） | 2–4 名 `sol-high` 按 DAG 并行 | 基线/回归重时增 1 名 `sol-high` ops；跨层风险加 `astra-high` | 主控维护契约、裁决审稿与文档；高影响合入留独立终审 |
| **大型**（多模块、多波次） | `N × sol-high` 仅并行就绪的互斥写集 | 独立 ops + 按域分片的只读 `astra-high`（疑难点升 `xhigh`） | 审稿量大时增 1 名 `gemini-4-neon-xhigh` 规划员；重要文档始终由主控把控 |

**并发上限**由最紧约束决定：就绪的互斥写集数、独立端口/测试库数量、配额与合入回归成本。共享契约未冻结或写集有重叠时先串行。

### 2. 标准协作流程

1. **契约先行**：冻结基线、公共接口、文件白名单、禁改区与验收命令，再派发执行者。
2. **隔离写入**：并行修改共享仓库时用 `workspace="share"` 或严格互斥子目录，并隔离测试端口与临时目录。
3. **精炼看板**：执行者只回报「状态、改动路径、命令与结果、遗留风险」；日志由单一维护者记录，**重要文档改动统一交回主控（Neon）处理**。
4. **临时兜底 SOP**：遇到 `sol-high` 持续阻塞、误拒或通道异常，先保住已有补丁并停止盲目重试；临时派 `gemini-4-hydrogen-xhigh` 接替该实现切片，完成后立即回收不持久化。未获用户授权不使用 Claude。
5. **串行合入与终检**：按依赖 DAG 串行合入；高风险变更在合入版本跑全量回归并由独立 `astra-high` 复核；视觉任务过 Neon 视觉验收；重要文档由 Neon 收尾更新。

## 二、五大专项蜂群蓝图

### 1. 大型代码库重构、全量测试与性能调优

- **适用**：跨模块重构、测试覆盖补全、性能调优、历史缺陷集中治理。
- **弹性配置**：按独立模块派 `1–6` 名活跃成员：可选 `sol-high` ops + 只读 `astra-high`（高风险点升 `xhigh`）+ `N × sol-high` 并行落地；Neon 负责裁决、拆包与重要文档更新。
- **流转与门禁**：
  1. **基线与风险地图**：ops 建隔离副本/基线提交、记录既有测试与性能基准，可与只读风险摸排并行。
  2. **证据审计**：`astra-high` 只读找出跨层不变量、并发与持久化缺陷，每条附复现与最小方案。
  3. **反过度防御拆包**：Neon 剔除冗余防御建议并拆成零重叠写集；`N × sol-high` 补红测、最小修复与绿测，只写局部日志不动重要文档。
  4. **串行合入与终审**：主控串行合入，独立 `astra-high` 查反序覆盖、内存峰值、身份漂移与性能口径；全量回归全绿后由 Neon 整理发布说明与文档。

### 2. 数学建模、算法仿真与科研实验

- **适用**：优化求解器、蒙特卡洛仿真、参数扫描、消融实验与统计验证。
- **弹性配置**：`1–5` 名活跃成员：Neon 定问题边界、评价指标与实验叙述；`astra-high`（硬核证明升 `xhigh`）负责推导与严谨性复核；`N × sol-high` 并行实现求解与实验脚本。
- **流转与门禁**：
  1. **目标与假设冻结**：Neon 明确优化目标、量纲、可接受假设、随机种子与数据隔离口径。
  2. **数学推导**：Astra 给出公式推导、边界条件、数值稳定性与数据泄露检查，区分严格证明与经验近似。
  3. **并行仿真**：`N × sol-high` 按求解器/参数网格/消融组并行编码、跑实验并落盘配置、种子与原始数据。
  4. **复现终审与成文**：独立 `astra-high` 按固定种子复核统计口径与极端算例；如需出版级图表与论文/报告正文，**由 Neon 审定图表审美与亲自执笔核心文本**，Sol 只写绘图与数据汇总脚本。

### 3. 3D/CAD 参数化建模与可视化（Blender / OpenSCAD / WebGL）

- **适用**：参数化零件与装配体、程序化网格、产品外观原型与 WebGL 交互展示。
- **弹性配置**：`1–6` 名活跃成员：**`gemini-4-neon-xhigh` 独占视觉与造型权**；`N × sol-high` 按部件编写参数脚本与自动渲染管线；`astra-high` 负责几何/工程审计。
- **流转与门禁**：
  1. **视觉与工程双契约**：Neon 先定比例、轮廓语言、材质、布光、镜头与参考视角；工程侧锁死单位、坐标系、原点与公差。
  2. **分部件建模**：`N × sol-high` 用 OpenSCAD / Blender Python / Three.js 实现参数化脚本、导出与多视角自动渲染，严禁私改比例与风格。
  3. **几何工程审计**：`astra-high` 检查流形与水密性、尺寸公差、装配干涉、坐标变换及着色器数学正确性。
  4. **多视角视觉终审**：每轮迭代必须由 Neon 审查同一配置的正/侧/斜视及细节渲染图并给出视觉修改指令；工程导出通过不等于视觉通过。

### 4. 前端 UI 原型设计与交互开发

- **适用**：界面原型、设计系统落地、复杂交互接线、响应式与无障碍改造。
- **弹性配置**：`1–5` 名活跃成员：**`gemini-4-neon-xhigh` 独占视觉设计与文案权**；`N × sol-high` 并行实现状态、接口接线、布局与 E2E 测试；高复杂交互配 `astra-high` 审计。
- **流转与门禁**：
  1. **设计规范先行**：Neon 冻结设计语言、排版层级、色彩与留白系统、克制动效、界面文案及组件契约。
  2. **按规范落地**：`N × sol-high` 实现状态管理、API 接线、响应式样式、无障碍属性与自动化测试，不得私改视觉风格或界面文案。
  3. **交互风险审查**：`astra-high` 专查状态竞态、异步请求乱序、内存泄漏与边界输入。
  4. **功能与视觉双门禁**：跑通交互与响应式测试后，必须由 Neon 在浏览器中逐一验收代表性视口、状态与动效细节。

### 5. 深度技术调研、授权逆向分析与架构评审

- **适用**：技术选型、跨层协议/源码机理剖析、迁移方案与架构评审。
- **弹性配置**：`1–5` 名只读成员按维度切片：常规源码/文档/日志采集派 `sol-high`，核心协议与状态不变量派 `astra-high`，**最终综合、ADR 与评审报告由 Neon 亲自撰写**。
- **流转与门禁**：
  1. **问题切片**：按模块、竞品或技术维度划分不重叠只读任务，先定待决策问题与备选方案。
  2. **并行取证**：Sol 汇总可追溯的源码位置、版本与关键摘录；Astra 厘清核心状态机、协议边界与反证。
  3. **误拒处理**：若底层二进制、解包或补丁分析在 GPT 侧触发误拒，立刻停止无谓争辩——拆分纯白盒只读分析，或将受阻的合法分析/验证脚本临时交由 `gemini-4-hydrogen-xhigh` 完成并随即回收。
  4. **决策定稿**：由 Neon 交叉核验多源证据、剔除过度设计，亲自撰写清晰可读的权衡矩阵与可执行 ADR（背景、备选、决策、影响、迁移与回退）。
