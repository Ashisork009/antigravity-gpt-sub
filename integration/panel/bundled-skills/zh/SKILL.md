# GPT-6.2 多模型协作指南

先定权责边界，再选模型与编排形态。`codex-gpt-6.2-sol-high` 和 `codex-gpt-6.2-astra-high` 统一以 **`high` 为默认起点**（不使用低于 `high` 的档位）；`Neon` 统一默认 **`gemini-4-neon-xhigh`**；蜂群按需启用，不搞固定编制。

## 六条核心边界

1. **GPT-6.2 不做最终拍板。** Sol 负责落地执行，Astra 负责深度审查与技术攻坚；架构取舍、优先级、范围界定与合入放行权归主控（`Neon`）或用户。
2. **审查建议必须过滤过度防御。** Astra 擅长抓真实 P0/P1 缺陷，但容易附带低收益防御项或重型改造（多余抽象层、新账本、线程池等）。审稿时把**缺陷事实**与**修复方案**拆开，只保留最小充分改动。
3. **重要文档与文案归 Neon，GPT 仅写日志与局部记录。** GPT 的防御性套话和冗余免责声明会破坏可读性：
   - **GPT 最多允许写**：运行日志、测试输出、局部改动记录、只读审查笔记。
   - **禁止 GPT 直接修改**：README、架构/设计文档、ADR、Skill/规则文档、对外说明及任何文案内容。
   - **重要文档由统筹者（`Neon`）统一维护**，所有文案撰写与润色均交给 `Neon` 成员处理。
4. **视觉与审美权归 `gemini-4-neon-xhigh`。** GPT-6.2 的视觉与造型品味弱于 Neon `xhigh`。前端界面、数据可视化、3D/CAD 外观均由 Neon 制定设计规范并看浏览器截图或多视角渲染图终审；Sol/Astra 仅按规范落地代码、接线、参数脚本与测试，不得擅自改风格或跳过视觉验收。
5. **模型池与兜底纪律。**
   - **Gemini 仅使用 `Neon` 与 `Hydrogen`**（不使用 Flash 等其他变体），且 **`gemini-4-hydrogen-xhigh` 仅作落实面临时兜底**：当 Sol 无法完成具体实现任务时，临时派发 `hydrogen-xhigh` 接替该切片，完成后立即回收，**不持久化常驻**，也不让它承担统筹、文档或审美工作。
   - **Claude 额度极少，默认禁用**，除非用户明确授权，否则不派发也不热切至 Claude。
6. **模态与误拒处理。** GPT 通道原生仅支持 `text` + `image`，不支持原生 PDF（须先提取文本或转图）。涉及底层补丁、逆向或重打包时 GPT-6.2 较易触发误拒，优先拆出纯源码白盒部分，或把受阻的合法落实切片临时交 `gemini-4-hydrogen-xhigh` 处理。

## 模型与档位矩阵

| 模型与档位 | 角色定位 | 典型用途 | 升级 / 约束 |
| :--- | :--- | :--- | :--- |
| **`codex-gpt-6.2-sol-high`** | **默认主力执行** | 并发开发、多文件修复、单测/回归、Git 与运维操作、仿真/建模脚本、运行日志与局部改动记录 | 统一从 `high` 起步，不用 `low`/`medium`；禁止改重要文档与文案 |
| **`codex-gpt-6.2-astra-high`** | **默认深审与攻坚** | 跨层架构与不变量审计、并发/一致性排障、数学与算法推导、合入前独立终审 | 统一从 `high` 起步，不用 `low`/`medium`；只出证据与最小建议，不拍板 |
| `codex-gpt-6.2-astra-xhigh` | 定点升级档 | 高风险有状态系统审计、疑难并发根因、硬核证明，或 `high` 两次未收敛 | 仅针对单一已证实瓶颈，绝不给常规并行开发使用 |
| `*-max` | 极罕见封顶档 | 高损失、证据冲突且 `xhigh` 仍无法闭环的单点复核 | 设明确退出条件，禁止占用并行执行槽位 |
| **`gemini-4-neon-xhigh`** | **主控 / 规划 / 审美 / 文档（默认档）** | 统筹编排、反过度防御裁决、UI/3D 设计与视觉验收、重要文档与文案精修 | 统一默认 `xhigh`；主控保持轻量，不亲自啃大段源码、写常规业务或跑长测 |
| `gemini-4-hydrogen-xhigh` | **临时落实兜底** | Sol 无法完成的具体实现切片临时接替 | **用完即撤、不持久化**；不负责统筹、审核、审美或重要文档 |
| Claude Sonnet / Opus | 保留（默认禁用） | 仅在用户明确授权时启用 | 默认不分配、不热切 |

**档位经济性：** `high` 是最佳性价比拐点。继续升至 `xhigh`/`max` 边际收益很小（外部基准示意 Astra `high` ~60 → `max` ~62），但延迟与推理 token 常涨 2–4×，`max` 单任务可达数分钟至十几分钟；Sol 单位配额消耗约为 Astra 的 1/4。难题一旦闭环，立刻把实现与测试交回 `sol-high`。

## 弹性编排原则

按 **独立写集 × 风险等级 × 依赖 DAG** 动态定人数，严禁套用固定人数模板：

| 规模 | 建议起点 | 扩缩信号 |
| :--- | :--- | :--- |
| **小型** | 主控直接定方案，派 1 名 `sol-high` 落地；无需单独 ops、Astra 或规划员 | 涉及非显而易见的契约风险时，补 1 次 `astra-high` 只读审查 |
| **中型** | 按互斥写集并行 `2–4` 名 `sol-high`，主控管契约与重要文档 | 跨层状态/并发复杂时加 `astra-high`；基线和回归繁重时分出 1 名 `sol-high` ops |
| **大型** | 基线与风险地图先行，再按 DAG 分波次并行 `N × sol-high` 与串行合入 | 仅在有独立写集、独立端口和足够配额时加人；审查体量大时再分出 `gemini-4-neon-xhigh` 规划员 |

- **主控轻量化**：把大段源码阅读、常规编码、测试回归和日志整理派给 `sol-high`，主控只读精炼结论、做裁决、管重要文档与做视觉终审。
- **单写主责**：每个写集只归一名作者；并行修改共享目录时使用 `workspace="share"` 或互斥子目录。
- **工具选用**：独立一次性任务用普通子代理；多阶段流水线用 `run_workflow`；用户启用 `/swarm` 且需要共享看板与接力时使用蜂群。

## 派发与收口清单

派发执行者前写清五要素，避免越界扩 scope：
1. **可写白名单**：精确到文件/目录（注明禁止触碰重要文档与对外文案）。
2. **冻结区**：共享配置、公共接口、迁移脚本或不可变行为。
3. **共享契约**：接口签名、数据不变量与上游依赖。
4. **停止与升级条件**：预算上限或阻塞信号，遇阻立刻回报主控。
5. **可复验验收命令**：明确命令与通过标准。

**收口节奏：**
- Astra 审查按「复现证据 → 受损契约 → 影响 → 最小修复」逐条由 Neon 标记 **采纳 / 裁剪 / 驳回**。
- 按 DAG 串行合入，高风险改动由独立 `astra-high` 在合入版本终审；涉及 UI/3D 时过 Neon 视觉验收；重要文档与对外说明统一由 Neon 在收口阶段更新。

## 异常与兜底

- 仅调用工具或短暂静默不代表卡死，按事件通知推进，不空转轮询。
- 若 `sol-high` 遇反复空输出、误拒或无法落地，先保存已有进度，停止盲目重试：写冲突则转串行；单切片落实受阻则由主控临时派 `gemini-4-hydrogen-xhigh` 接替该切片，交付后即回收；未经用户授权不切 Claude。
